# Практическая работа №2. Вариант 14

Программа на Python для построения графа зависимостей npm-пакетов.

## Возможности

- Проверка параметров командной строки.
- Получение зависимостей выбранной версии из реестра npm.
- Итеративный обход в глубину с ограничением глубины.
- Обработка циклов и общих зависимостей.
- Работа с тестовым графом из JSON.
- Вывод прямых и обратных связей построенного графа.
- Сохранение схемы Mermaid и изображения PNG.

## Требования

Python 3.10 или новее.
Для создания PNG нужны Node.js и Mermaid CLI.

Установка Mermaid CLI:

```powershell
npm.cmd install -g @mermaid-js/mermaid-cli --allow-scripts=puppeteer
```

Данные о зависимостях программа получает через стандартную
библиотеку Python, без вызова npm.
Mermaid CLI используется только для создания изображения.

## Параметры

| Параметр | Назначение |
|---|---|
| --package | Имя пакета |
| --repository | URL реестра или путь к тестовому JSON |
| --test | Использовать тестовый JSON |
| --version | Точная версия исходного пакета |
| --output | Путь к изображению PNG |
| --max-depth | Максимальная глубина, целое число от 0 |
| --help | Справка |

Все параметры, кроме --test и --help, обязательны.
Папка для сохранения должна существовать.
В тестовом режиме --version проверяется, но не используется:
узлы JSON задаются именами без версий.

## Запуск

Команды выполняются из корня проекта.

```powershell
.\run.bat --package express --repository https://registry.npmjs.org --version 4.18.2 --output express.png --max-depth 3
```

Можно запустить напрямую:

```powershell
python src/main.py --package express --repository https://registry.npmjs.org --version 4.18.2 --output express.png --max-depth 3
```

Результат: текстовый вывод связей, express.mmd и express.png.
Стрелка A → B означает, что A зависит от B.

При глубине 0 граф содержит только исходный пакет.
Узлы на предельной глубине сохраняются без раскрытия зависимостей.
Сообщение «нет раскрытых зависимостей» может означать как отсутствие
зависимостей, так и достижение ограничения глубины.

Обратные связи показывают, какие узлы построенного графа используют
данный пакет. Поиск по всему реестру npm не выполняется.

## Тестовый режим

```powershell
.\run.bat --package A --repository examples/repository.json --test --version 1.0.0 --output graph.png --max-depth 3
```

Формат JSON: имя пакета и список его зависимостей.
Имена состоят из заглавных латинских букв.
Каждая зависимость должна присутствовать в JSON как отдельный ключ.

Пример содержит цикл A → B → D → A,
общую зависимость D и изолированный пакет F.

## Примеры

| Пакет | Версия | Глубина | Результат |
|---|---|---|---|
| express | 4.18.2 | 3 | Большой граф с общими зависимостями |
| chalk | 4.1.2 | 3 | Две ветки зависимостей |
| lodash | 4.17.21 | 3 | Один узел без зависимостей |

В репозитории сохранены соответствующие файлы .mmd и .png.

## Сравнение с npm

Прямые зависимости проверялись командами:

```powershell
npm.cmd view express@4.18.2 dependencies --json
npm.cmd view chalk@4.1.2 dependencies --json
npm.cmd view lodash@4.17.21 dependencies --json
```

Имена прямых зависимостей совпали для трёх примеров.
npm view показывает объявленные условия версий.
Программа выбирает конкретные подходящие стабильные версии
и раскрывает зависимости до указанной глубины.

Для Chalk условия ^4.1.0 и ^7.1.0 дали версии
ansi-styles@4.3.0 и supports-color@7.2.0.
Для Lodash npm не вывел зависимостей.

Дополнительно выполнено сравнение с деревом установленного
npm-проекта для express@4.18.2, chalk@4.1.2 и lodash@4.17.21:
npm.cmd ls --all --depth=3

## Ограничения

Обрабатывается поле dependencies.
Поддерживаются точные стабильные версии, сокращения 2 и 2.1,
шаблоны 2.x и 2.1.x, сравнения с полной и сокращённой версией,
условия ^ и ~, включая ^1 и ~1.2, диапазоны через дефис
вида 1.0.0 - 2.0.0, сочетания условий через пробел и оператор ||.

Полная совместимость с npm semver не реализована.
Предварительные версии зависимостей при подборе исключаются.
Неподдерживаемое условие приводит к сообщению об ошибке.
